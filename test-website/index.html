Image download tests

For Firefox 140+. Expected filenames assume the add-on’s default settings.

INSTRUCTIONS
  1. 01
    Use the add-on’s default settings.
  2. 02
    Right-click an image and select the add-on’s Save image entry.
  3. 03
    Compare the download with the expected result. Mark passed or failed; reloading clears results.
Serve this folder over HTTP. File URLs are rejected by the add-on. From the repository root, run pnpm run start:test-website, then open http://127.0.0.1:8080.

Settings

Change one setting at a time, then save a PNG above.

Destination & filename
An empty target folder uses Firefox’s downloads directory. Subfolders stay inside it. Domain folders use this page’s hostname; domain prefixes replace dots with underscores. Timestamps use local time.
Repeat downloads
Save an image twice with timestamp prefixes off. “Create a unique name” keeps both; “Overwrite” replaces the file; “Skip” requires a matching completed file that still exists and remains in Firefox’s download history.
Automatic tab closing
Test in a disposable tab. It should close after a successful download completes, and stay open after failure or a skipped download.
Browser-selected filenames
Empty the target folder, disable domain subfolders and prefixes, and use “Create a unique name” or “Overwrite”. Firefox then chooses most HTTP(S) filenames.
Referrer compatibility
Local files should download in all referrer modes. Testing authentication, referrer rejection, redirects, and Content-Disposition requires a separate server.
Filename edge cases
CDN suffixes, Windows device names, and the 180-byte filename limit are covered by the repository’s automated tests. Colon-containing filenames cannot be stored on Windows.
